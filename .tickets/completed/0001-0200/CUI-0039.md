## 問題描述

`lifeuk.wrongList` / `lifeuk.practiceFlags` 係 `{ "exam.idx": true }`。載入時冇檢查 key 有冇對應題目：

- `renderMyReview` 用 `questionGroups(keysOf(wrongList)).length` 數，過時 key 都計一題 → tile 數字多咗。
- 撳 tile → `startExam(WRONG_EXAM)` → `reviewSetPool` → `questionByKey(k)`：
  - exam 唔存在（`99.99`）：`EXAMS[99][99]` → `TypeError: Cannot read properties of undefined (reading '99')`
  - exam 存在但 index 超出（`1.999`）：`{ q: undefined }`，之後 `TypeError: … (reading 'o')`
- 結果：uncaught page error，畫面停喺 Home，**連清單入面真嘅題目都溫唔到**（tile 等於壞咗），一直到用戶清 progress。

幾時會有過時 key：題庫更新刪題 / 重新排 index、舊版 merge 落嚟嘅資料（`MERGE_LS`）、手改 storage。

## 重現步驟

1. DevTools：`localStorage.setItem('lifeuk.wrongList', '{"1.999":true,"1.2":true}')`；`lifeuk.homePrefs` = `{"mode":"practice"}`

## 修正（2026-10-13，branch `claude/charming-archimedes-hrh4wd`，開發時叫 v2.0.6，以 v2.1.1 發佈）

一個地方解決：載入時 prune，所有 consumer 讀到嘅都係乾淨清單（冇逐個 consumer 加 guard）。

- `js/domain/questions.js`：新 `isValidQuestionKey(k)` —— key 要係字串、exam 存在、index 喺範圍內，而且 `qKey({ examNum, origIdx }) === k`（round-trip：`1.2.3`、`01.2`、`1.02`、`abc`、`''` 都唔算）。G40 同文字題嘅每個 copy 都係真 key，照留。
- `js/core/store.js`：新 `pruneStaleQuestionKeys()` —— `streaks`（`lifeuk.practiceStreak`）、`practiceFlags`、`wrongList` 過濾一次；只有 `{ key: value }` object 少咗 key 先 `setLS` 寫返（idempotent：乾淨嘅載入一次都唔寫）；唔係 object 嘅值（字串 / array）storage 原封不動，記憶體當空清單（之前 `keysOf("oops")` 會變 `0…3` 再 throw）。
- `js/main.js` `startApp()`：`applyTranslation()` 之後、任何 render 之前 call（`typeof` guard，W-057 舊 cached `store.js`）。`getLS` 喺 `store.js` 載入時已經做咗 lazy legacy migration（`MERGE_LS` / `LS_KEY_FALLBACK`），prune 喺佢之後，寫入經 `setLS` → `lsKey`，fallback 舊 key 照用；merge 返嚟嘅過時 key 下次載入再 prune。
- Consumer 審查：Home tile 數（`renderMyReview`）、`reviewSetPool`（錯題 / 旗標輪）、Flagged 畫面（`openFlagged`）、結果頁「仲有 N 題」（`result.js`）、Review 答啱清走（`quiz.js` `planSameQuestionKeys(keysOf(wrongList))`）、計劃 ctx `wrongKeys`（review / wrong-facts task）、`planMasteredKeys(streaks)`（過時 streak key 唔再計入 mastered set）—— 全部讀 prune 咗嘅 `let`。其他 `questionByKey` caller（`fact.src`、記憶法 `qkeys`、Similar、計劃 `planFactQids`、`addWrong(q)` / `setPracticeFlag`）用資料本身嘅 key，唔係 stored key。
- Review v2.0.6（`.proj-docs/reviews/2026-10-13_review_v206.md`）跟進：**S-262** v2.1.1 之前已經 materialize 咗、存喺 `lifeuk.studyPlan` 嘅 review task `qids` 可能抄咗過時 key（`planMaterializeReview` 直接 map `wrongKeys`）→ `js/domain/planProgress.js` `planTaskQids()` 用 `isValidQuestionKey` 過濾、`planTaskProgress()` 經佢數（`plan-run-test` `checkStaleReviewQid`）。**S-263** wrong-facts `anchor` 冇風險（`FACT_BY_QKEY[k]` 搵唔到就 skip，之前呢度寫錯）。**W-075** `pruneStaleQuestionKeys` / `planTaskQids` `typeof isValidQuestionKey` guard（HTTP cache 舊 `questions.js` + 新 `store.js` 會 Home 空白；`upgrade-test` case 13）。**S-264** `stale-keys-test` 加 legacy 無 prefix `wrongList` → migrate 再 prune。
