## 根本原因（RCA）

答題 → `renderQuestion` 重寫 `#optionsContainer`、卡頂 Translate 掣變 ← →、`fitQuiz` 先除晒 `is-tight`／`is-compact` 再逐步加返。量度（`renderQuestion` 前後、每個 frame 記低左欄 `scrollTop`／`scrollHeight`／`#qText` top）證實有三個原因疊埋：

1. **`.opt` 嘅 `transition: all 0.15s` 連 `is-compact` 嘅 padding 都 ease**（主因，令 fit 唔穩定）：新 options 一加 `is-compact`，padding 由大慢慢縮，`fitSteps` 同步量到嘅係起步 padding。結果 fit 睇上一次 render：同一題第一次 render max scroll 107 → 下一 frame 97 → re-render 先係 79（中文大字 Q21）；有啲題第一次唔加 step、re-render 先加。render 後 0.15s 內欄高仲喺度變，scroll 被夾、內容郁。
2. **Browser scroll anchoring**：同步 render 時 `scrollTop` 冇變，但下一個 frame anchoring 再調 `scrollTop`（約 +10px，例如 33 → 43），題目文字向上移。
3. **卡頂 header row 變矮**：英文大字未答時 Translate 掣令 `#qNum` row 高 43.8px，答完換做 ← → 只得 20px，題目文字本身上移約 5.4px（所以中文大字冇呢個問題）。

（QA 見到「碌到一半再答會彈去底」只係 Playwright `page.click` 會先將 option scroll 入 view；test 改用 DOM click。）
