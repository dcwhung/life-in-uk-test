## 問題描述

`#planExamDate` 有 `data-blur-action="planCommitExamDate"`。撳 date field 以外嘅 chip 時，事件次序係 mousedown（/ touchstart）→ date field `focusout` → `planCommitExamDate()` → `renderPlanGoal()` → `renderPlanDays` / `renderPlanRest` / `renderPlanLevels` 用 `innerHTML` 重建全部 chip 同程度卡 → mouseup 落喺**新**嘅 element。因為 mousedown 同 mouseup 嘅 target 唔同，`click` 只會派去共同 ancestor（`#planDaysChips` 等，冇 `data-action`），所以呢一下冇任何效果，focus 跌落 `BODY`。

Review Round 2 寫「mousedown → focusout commit → click action，結果正確（chip 會覆蓋）」，但實際 click 冇去到 chip。`#planCreateBtn` / ← 主頁係靜態 markup，唔受影響。

## 重現步驟

1. `?preview=plan` → 主頁「Create a study plan」卡 → 目標畫面
2. 撳入日期 field（或者手機用原生 picker 揀一個日期，picker 關咗之後 input 仍然有 focus）
3. 撳一下「2 weeks」chip（或者任何休息日 chip / 程度卡）

QA script：`.proj-docs/qa/scripts/2026-10-08_qa-plan-pr3-browser.js`（`QA_ONLY=F`，F11b 三個 case、F19b phone `fill` + `tap`）

## 預期結果

一下就揀中：考試日期變 14 日 / 休息日切換 / 程度改變。

## 實際結果

冇變（draft 不變、chip 冇 active），`document.activeElement = BODY`；要再撳第二下先得。桌面（mouse）同手機（touch + 原生 picker）都會中。

## 建議修正

- 方案 A：`planCommitExamDate` 只喺 draft 真係有改先 `renderPlanGoal()`；冇改就淨係 `byId('planExamDate').value = planGoalDraft.examDate`（大部份情況 date 已經喺 input 時收咗，commit 冇嘢改，chip 唔會被重建）。仍然要處理「超過 max → clamp」嗰種 case。
- 方案 B（更徹底）：chip / 休息日 / 程度卡改做原位更新 class + `aria-pressed`（同 W-032 switch 一樣），唔再 `innerHTML` 重建；咁 S-109 focus helper 都可以簡化。
- 加 test：focus date field → `page.click` chip 一次 → draft 已更新（用真 click，唔好用 `evaluate`）。

## 解決方案（完成後填寫）

`js/screens/planGoal.js`：
- `planSyncGroup` / `planSyncChips`：preset chip、休息日 chip、程度卡只建立一次，之後原位更新 `.active` / `.selected`、`aria-pressed` 同文字（語言切換都係原位改字），唔再用 `innerHTML` 重建。mousedown 觸發 date field `focusout` commit 之後，click 仍然落喺同一粒掣
- `planCommitExamDate`：draft 冇變就唔 `renderPlanGoal()`，只將 field 寫返 draft
- S-109 嘅 focus helper 唔再需要（掣冇被換走，focus 自然留低），已刪
- `tests/plan-ui-test.js`：`checkClickAfterDate`（focus date → 真 click 休息日 / preset / 程度卡一下即生效；打完日期再 click chip 兩樣都生效）、`checkTapAfterDate`（`hasTouch` + `isMobile`，`fill` 日期後 `tap` chip）
