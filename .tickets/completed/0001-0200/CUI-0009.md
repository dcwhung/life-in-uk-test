## 問題描述

`css/screens/study.css` 寫住「32px box + 6px invisible ring = 44px touch target (WCAG 2.5.5)」，HANDOFF 都寫「約 44px 可撳範圍」。實際上差幾 px，原因有兩個：

1. `::before` 係 `position: absolute`，`inset` 由 containing block 嘅 **padding box** 計，唔係 border box。`.fact-btn` 有 `1.5px` border（Chromium 1x DPR 計做 1px），所以 -6px 只係伸出可見邊 5px：32 + 5 + 5 = 42px，唔係 44px。
2. W-009 之後相鄰兩邊只伸出 gap 一半（-2px from padding box，可見邊外 1px），所以橫向再少：書籤 = 5 + 32 + 1 ≈ 38–39px，✓ 一樣。

功能正確（W-009 已解決重疊，兩粒掣可見範圍內每一點都撳中自己），WCAG 2.5.8（AA，24px）有餘；只係同 plan O2 / 註解講嘅 44px（WCAG 2.5.5 AAA）唔一致。

3. QA script `.proj-docs/qa/scripts/2026-10-06_qa-v062.js`（`hitAreas`）逐 px 掃：書籤 hit 橫向 -6…32（≈39px）、縱向 -6…36（≈43px）；✓ 橫向 34…72（≈39px）

每粒 fact 掣可撳範圍 ≥ 44px 高（plan O2），或者文件改返講實際數字。

## 建議修正

- 方案 A（最細改動）：ring 以 border box 計 —— `inset: calc(-6px - 1.5px)`（或抽 `--fact-btn-border: 1.5px`），相鄰邊 `calc(var(--fact-actions-gap) / -2 - 1.5px)`。縱向變 44px；橫向因為 gap 只有 4px，最多 32 + 6 + 2 = 40px。
- 方案 B：接受現狀，改 `study.css` 註解同 HANDOFF 做「約 42px 高 / 39px 闊（AA 24px 有餘）」。
- 推薦：A（縱向達到 44px，同 plan 一致），加 `study-test` 斷言「掣外 5.5px（上 / 下）仍然撳中」。
