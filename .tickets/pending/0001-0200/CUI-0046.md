## 問題描述

`planRunBackName()` / `planQuizBackName()` 嘅 W-072 fallback 寫明「a stale locale without them is named by the visible word itself, never a raw key」，即係檢查 `name === nameKey`。但 `t()`（`js/core/i18n.js` `resolveKey`）喺現語言冇 key 時會 fallback 去 **英文**，唔會返 key；所以 zh-HK UI 用舊 `zh-HK.js`（冇 `plan.run.backTodayLabel` / `backDayLabel` / `backFactLabel`）時：

- 可見字：「返回」（`quiz.back`，舊 locale 已有）
- `aria-label` / `title`：「Back to today's tasks」/「Back to the fact」（英文）

可見字唔喺 accessible name 入面（voice control 講「撳返回」對唔到），亦同 W-077 要求唔一致。

證據（script `U`，390px zh-HK）：

| 舊檔 | `#planRunBack` | 計劃知識點練習 header |
|---|---|---|
| `c6b0806:locales/zh-HK.js`（v2.0.2） | 「返回」/ name「Back to today's tasks」 | 「返回」/ name「Back to the fact」 |
| `fb5cc7b:locales/zh-HK.js`（`main` v2.2.0，實際升級人口） | 同上 | 同上 |

同一原因令 Flagged / Study 入口喺舊 zh-HK.js 顯示英文可見字「Flagged」/「Study」（v2.0.5 QA O-2，已接受）——嗰度可見字同 name 一致，所以唔係 Label in Name 問題；本 ticket 只針對計劃兩粒掣（name 同可見字唔同語言）。
