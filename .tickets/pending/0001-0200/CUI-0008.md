## 問題描述

`promptInstall()`（`js/pwa/pwa.js`）有兩個問題，都係 v0.59 已經存在，唔係 v0.60 引入：

1. **Dead button（同 review S-020）**：native install 對話框撳取消（`userChoice.outcome === 'dismissed'`）之後，`deferredPrompt = null` 但 banner 仍然顯示；再撳 Install 冇任何反應。v0.60 加咗 ✕，用戶有路收起，所以影響減輕咗。
2. **Double activation（QA 新發現）**：`deferredPrompt` 要等 `await userChoice` 之後先清走，所以同一個 event 期間第二次觸發 `promptInstall()`（double tap / 快速兩下 Enter）會再 call 一次 `prompt()`。Chromium 規定每個 `BeforeInstallPromptEvent` 只可以 `prompt()` 一次，第二次會 reject `InvalidStateError`；因為冇 await 冇 catch，會出 unhandled promise rejection（console error）。功能上冇壞（第一個 prompt 照出），只係 console noise。

## 重現步驟

1. 觸控裝置（或 `isMobile` + `hasTouch` emulation），等 Chrome 發 `beforeinstallprompt`，banner 出現
2. （問題 1）撳 Install → native 對話框撳「取消」→ banner 仲喺度 → 再撳 Install → 冇反應
3. （問題 2）同一個 event 之下即刻撳兩下 Install（或 console 跑 `Promise.all([promptInstall(), promptInstall()])`）

## 預期結果

1. `dismissed` 之後 banner 收起（唔寫 `lifeuk.installDismissed`，下次 Chrome 再發 event 先再出），或者 Install 掣唔再係死掣
2. `prompt()` 每個 event 最多 call 一次，冇 unhandled rejection

## 實際結果

1. QA script：outcome `dismissed` → `{"visible":true,"v":null}`，banner 留低，`deferredPrompt` 已經係 `null`
2. QA script（假 event，`prompt` 係 stub）：兩次 `promptInstall()` → `prompt()` 被 call 2 次。真 event 第二次會 reject（按 Chromium 行為推斷，headless 冇真 event 可以重現）

## 建議修正

```js
async function promptInstall() {
  if (!deferredPrompt) return;
  const ev = deferredPrompt;
  deferredPrompt = null;            // claim the event before awaiting: a second tap is a no-op
  ev.prompt();
  await ev.userChoice;
  byId('installBanner').classList.remove('visible');   // either outcome: the event is spent
}
```

另外可以考慮 listen `appinstalled` 收 banner（review S-020 方案 A）。補測：`pwa-test` 加 `dismissed` outcome 收 banner、雙擊只 call 一次 `prompt()`。
