## 問題描述

`startFactPractice(factId)`（`js/screens/sideSession.js`）每次都寫一個新嘅 `sessionReturn = { kind: 'study', scrollY: window.scrollY }`。如果已經喺 fact session 入面再 call 一次（PR-3 嘅「▶ Practise these N」掣 double activation、鍵盤連撳兩下 Enter，或者將來由 session 內再開），第二次記低嘅係 quiz 畫面嘅 `scrollY`（`startSideSession` 已經 `scrollTo(0, 0)`），所以 ↩ Back 返 Study 會停喺頂部，唔係用戶原本嘅位置。

同理，喺 Similar session 入面開 fact session（E4）會丟咗原本嘅 quiz session（`sessionReturn` 被覆蓋）；呢個 QA 認為係合理行為（Back 返 Study），但 PR-3 要確認係有意。

v0.62 冇入口掣，用戶撞唔到；記錄低等 PR-3 接掣嗰陣一齊處理。

## 重現步驟

```js
openStudy(); studySetTab('chapters'); studySetChapter(3); scrollTo(0, 500);
startFactPractice(21); startFactPractice(21);
sessionReturn.scrollY   // 0（應該係 500）
```

## 預期結果

第二次 call 唔應該覆蓋 Study 嘅返回位置（`scrollY` 仍然係 500）。

## 實際結果

`scrollY` 變 0；↩ Back 之後 Study 停喺頂部。

## 建議修正

- 方案 A：`startFactPractice` 開頭 `if (isSideSession() && sessionReturn.kind === SESSION_RETURN_KIND.study) { 沿用舊 sessionReturn }`，即只換題目唔換返回點。
- 方案 B：PR-3 入口掣 handler 做 guard（第一下之後 screen 已經轉咗，正常 click 撞唔到；只防 programmatic / 鍵盤 repeat）。
- 推薦：A（引擎層一次過處理），`factsession-test` 加「連 call 兩次，↩ Back scrollY 仍然還原」。
