## 根本原因（RCA）

答題 → `renderQuestion` 重寫 `#optionsContainer`、卡頂 Translate 掣變 ← →、`fitQuiz` 先除晒 `is-tight`／`is-compact` 再逐步加返。量度（`renderQuestion` 前後、每個 frame 記低左欄 `scrollTop`／`scrollHeight`／`#qText` top）證實有三個原因疊埋：

1. **`.opt` 嘅 `transition: all 0.15s` 連 `is-compact` 嘅 padding 都 ease**（主因，令 fit 唔穩定）：新 options 一加 `is-compact`，padding 由大慢慢縮，`fitSteps` 同步量到嘅係起步 padding。結果 fit 睇上一次 render：同一題第一次 render max scroll 107 → 下一 frame 97 → re-render 先係 79（中文大字 Q21）；有啲題第一次唔加 step、re-render 先加。render 後 0.15s 內欄高仲喺度變，scroll 被夾、內容郁。
2. **Browser scroll anchoring**：同步 render 時 `scrollTop` 冇變，但下一個 frame anchoring 再調 `scrollTop`（約 +10px，例如 33 → 43），題目文字向上移。
3. **卡頂 header row 變矮**：英文大字未答時 Translate 掣令 `#qNum` row 高 43.8px，答完換做 ← → 只得 20px，題目文字本身上移約 5.4px（所以中文大字冇呢個問題）。

（QA 見到「碌到一半再答會彈去底」只係 Playwright `page.click` 會先將 option scroll 入 view；test 改用 DOM click。）

## 修正（2026-10-12，branch `claude/beautiful-cerf-makp0n`，086e684；v2.0.3 cdc2595）

- `css/screens/quiz.css`（只喺 ≥ 1024px media query）：`.quiz-main .opt` 只 ease 顏色（`transition-property: border-color, background-color, color`），padding 即時到位，fit 一次量啱；`.quiz-main { overflow-anchor: none }`。
- `js/screens/quiz.js`：`holdQuizMainView()` 喺 `renderQuestion` 第一行（DOM 未改之前）、同一題（`quizRenderedQuestion` 相同）而且左欄有碌時，記低第一個見到嘅元素（`#qText`，否則第一粒仲見到嘅 `.opt`；用 id，因為 options 會重寫）嘅 viewport top；`fitQuiz` 喺 `fitSteps` 之後、`runRefits` refresh fades 之前補 `scrollTop`，令佢返原位（頭尾由 browser 夾住）。`renderQuestion` 尾清走 hold，唔會帶去之後嘅 resize。換題（CUI-0033 `forgetQuizPanelsOnNewQuestion`／`topQuizPanelsOnNewQuestion`）照舊由頂開始；< 1024 冇 `quizDesk.main` 顯示，乜都唔做。
- `tests/desktop-quiz-test.js`：`checkMainKeptOnAnswer`（1024×600 EN 大字、1024×600 中文大字、1280×720 EN 大字 + Translate——1280×720 唔開翻譯 Exam 1–17 都冇題要碌）。每個 frame 後量，搵出成套題（套題固定，只係次序隨機）入面所有未答時左欄要碌嘅題，逐題 × 碌到底／碌到一半 → DOM click 答 → 第一個見到嘅元素移動 ≤ 2px，或者已夾到頭／尾；fades 跟 scroll。
