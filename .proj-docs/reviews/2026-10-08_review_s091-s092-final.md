### 驗證咗嘅嘢

1. **`‌‍` 喺 `u` flag class 入面**：合法，冇問題。`/[‌‍\p{ID_Continue}]/u.test('‍') === true`。喺 Node 20.20 / 21.7 / 22.22（Unicode 16.0 / 15.1 / 16.0）入面，`\p{ID_Continue}` 本身已經包咗 U+200C / U+200D，所以明確列出嚟係重複但冇害：不論加唔加，結果都一樣（probe 嘅 `noZW` 欄全部一致）。佢只係對 Unicode < 15.1 嘅 ICU 先有作用。呢部機冇咁舊嘅 Node，所以冇辦法實測「冇咗會變紅」；但 UAX #31 15.1 將 ZWNJ / ZWJ 加入 ID_Continue 呢個前提正確。
2. **註解準確性（L74–80）**
   - 「`\p{ID_Continue}` 要 `u` flag」✓
   - 「ZWNJ / ZWJ 由 Unicode 15.1 先入 `\p{ID_Continue}`（older Node）」✓。註解冇寫死 Node 版本號，呢個做法啱，因為支唔支援係睇 bundled ICU，唔係睇 Node major 版本：Node 20.20 都係 Unicode 16.0。相反，`b752df8` 嘅 commit message 寫「since Unicode 15.1 (Node 22)」就唔夠準，不過 history 唔改。
   - 「known gap：`a\u{62}in` 仍然當 keyword」✓（`REGEX_AFTER.test('a\\u{62}in') === true`）
   - 「加 `}` 會整壞 `}return /x/`」✓（而家 `'}return'` → true；如果 lookbehind 加 `}` 就會變 false，`if (x) {}return /x/` 嗰個 regex 會被誤讀成除號）
