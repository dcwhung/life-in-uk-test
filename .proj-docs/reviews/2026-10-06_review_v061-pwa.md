### CUI-0008 / S-020（`js/pwa/pwa.js`）
- 先 claim：`const ev = deferredPrompt; if (!ev) return; deferredPrompt = null;` 喺第一個 `await` 之前，所以同一 event 第二次 call 係 sync no-op。✓
- `Promise.all([ev.prompt(), ev.userChoice])` 對真 `BeforeInstallPromptEvent` 嘅語意：
  - 正常情況：Chromium `prompt()` 喺用戶揀完先 resolve，`userChoice` 同時 resolve → 兩者一齊 settle，冇額外延遲。
  - `prompt()` reject（`InvalidStateError` 重複 prompt、`NotAllowedError` 冇 user activation）：`userChoice` 會一直 pending，但 `Promise.all` 一有 reject 即 short-circuit，**唔會卡住**。之後 `userChoice` 就算遲咗 reject，`Promise.all` 已 attach handler，唔會出 unhandled rejection。
  - Reviewer 用 ad-hoc Playwright probe 驗證（HEAD code）：`prompt()` reject + `userChoice` 永遠 pending → `promptInstall()` 1 秒內 resolve、banner 收起、`lifeuk.installDismissed` = `null`；第二個 case `userChoice` 喺之後 reject → `pageerror` / console error 都係 0。
  - 比 ticket 建議嘅 `ev.prompt(); await ev.userChoice;` 更好：舊寫法 `prompt()` reject 會變 unhandled。
- 任何 outcome（accepted / dismissed / reject）都 `hideInstallBanner()`，`dismissed` 唔寫 dismiss key。✓ 同 S-020 方案 A。
- `dismissInstallBanner()` 重用 `hideInstallBanner()`，`setLS` 只喺 ✕ 路徑。✓
- `appinstalled`：iOS / Safari 唔發呢個 event，listener 永不觸發；冇 banner 顯示時 `classList.remove('visible')` 係 no-op；`#installBanner` 喺 `index.html` 靜態存在（L57），`byId` 唔會 null。無害。✓
- `catch {}`（optional catch binding）codebase 已廣泛使用（`utils.js`、`main.js`），唔係新 syntax 風險。

### 🟢 S-026 — `prompt()` reject 路徑（try/catch）冇自動化測試
- 位置：`tests/pwa-test.js`；`js/pwa/pwa.js` `promptInstall()` catch 分支
- 描述：CUI-0008 第 2 點本身就係「reject 唔可以變 unhandled」，但測試嘅假 `prompt()` 永遠成功；catch 分支同「`userChoice` 永遠 pending 唔會卡住」只靠 reviewer 手動 probe 驗證。將來有人改返 `await ev.prompt(); await ev.userChoice;` 呢類寫法就會靜靜退化。
- 方案 A：加 `checkInstallPromptRejected`：`prompt = () => Promise.reject(new DOMException('', 'InvalidStateError'))`、`userChoice = new Promise(() => {})`，`Promise.race` 加 timeout 斷言 `promptInstall()` resolve、banner 收起、dismiss key `null`、`pageerror` 0。成本細。
- 方案 B：擴展 `fireCountingPrompt` 接受 `{ reject: true }` 參數，重用現有 helper。少 code，但 helper 參數變多。
- 推薦：A（意圖最清楚）。

### 🟢 S-027 — `appinstalled` 之後 `deferredPrompt` 仍然留住舊 event
- 位置：`js/pwa/pwa.js` `window.addEventListener('appinstalled', hideInstallBanner)`
- 描述：由瀏覽器選單安裝之後，banner 收起但 `deferredPrompt` 仍指向已用唔到嘅 event。實際冇路觸發（banner `display:none`，Install 掣唔可撳 / 唔可 focus），所以只係狀態唔乾淨。
- 方案 A：`appinstalled` handler 改做 `() => { deferredPrompt = null; hideInstallBanner(); }`。
- 方案 B：維持現狀，喺 listener 旁加註解講明 banner 已隱藏所以唔使清。
- 推薦：A（一行，狀態同 UI 對齊）。
