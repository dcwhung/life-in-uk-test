## 總評

主修正（`html { overscroll-behavior-y: none }`）啱位、細、冇副作用：Chrome（Mac / Android）同 Safari 16+ 都支援 root `overscroll-behavior`，`.plan-day-scroll` 自己嘅 `contain` 唔受影響（test 有驗）。`body::before` 帶本身好乾淨：body 冇 position，所以 containing block 係 initial containing block，`bottom: 100%` 令佢成塊喺文件原點上面（負座標 overflow 唔可以 scroll 到），reviewer 量過 `scrollHeight` / `scrollWidth` / print `scrollHeight` 喺 320 / 390 / 1024px 同 `efa2af2` 完全一樣，`scrollTo(0, -200)` 仍然係 0，`elementFromPoint` 頂部仍然係 `HEADER`，全部截圖 test 冇變。

`structure-test` guard 改動冇削弱 S-190：reviewer 用 13 個 sample 試（`{ path }`、`{ 'path': … }`、`{ ...o }`、`opts` variable、多行有 path、`box(el)` 內含 `)` 等）全部仍然 flag，只放行完全冇 `path`、冇 `.` 嘅 inline object。

### 🟡 Warning

#### W-063 iOS 後備（`body::before` 負座標 navy 帶）喺真 WebKit rubber-band 可能唔會畫出嚟

- **位置**：`css/base/layout.css:16-26`；`HANDOFF.md` layout.css 行 + v1.4.3 版本行
- **描述**：條帶靠「bounce 時文件原點以上嘅內容會被畫出嚟」。Chromium headless 用 transform 模擬時當然會畫（transform 只係將成個文件移落，負座標內容變成正座標）。但 iOS WKWebView rubber-band 係 UIScrollView 嘅 content offset 變負，露出嘅位置一般由 scroll view 背景色（WebKit 嘅 under-page background，預設由 root / canvas 背景色決定）填，tile 覆蓋範圍通常 clamp 喺文件範圍內。用戶截圖正正係咁：gap 係 `body` 背景傳上 canvas 嘅 `--bg`。所以我**唔肯定** iOS 會畫呢條帶 —— 可能會，可能唔會；冇真機證據之前唔應該當佢有效。
- **影響**：
  - iOS 16+（包括用戶部 iPhone 大機會）：`overscroll-behavior-y: none` 本身應該已經停咗 root bounce，帶有冇效都冇所謂 —— 但呢點都未喺真機證實（S-223）。
  - iOS < 16 或者 WebKit 唔認 html 上嘅 overscroll-behavior：如果帶唔畫，用戶會繼續見到淺色 gap，而 CSS 註解 / HANDOFF 話「露出 navy」係錯嘅。
- **方案 A（推薦，要問用戶一個 trade-off）**：保留條帶，**另外**將 root 背景改 navy、body 自己畫 `--bg`：
  ```css
  html { overscroll-behavior-y: none; background: var(--navy); }
  /* body 已經有 background: var(--bg); min-height: 100vh —— body 背景唔再傳上 canvas，只畫 body 自己個 box */
  ```
  咁 canvas / under-page 色變 navy，無論 WebKit 用邊種方法填 overhang 都係 navy。Trade-off：仍然 bounce 嘅舊 iOS **底部** pull-up 都會露出 navy（唔係 `--bg`）；`body` `min-height: 100vh` 已經蓋住短頁，平時唔會見到 navy。`overscroll-test` 嘅 pull-up `--bg` assert 要改（見 S-225）。
- **方案 B**：維持現狀，但 tag 前喺真機（最好一部 iOS 16+ PWA，加一部舊 iOS 或者 Safari Technology Preview 關咗 overscroll-behavior）試；如果條帶唔畫，再轉方案 A。同時將 CSS 註解 / HANDOFF 改做「預期」而唔係事實。
- **推薦**：先做 B 嘅真機試（反正 HANDOFF 已經要求），結果出嚟前將註解 / HANDOFF 字眼收細；如果用戶接受底部 navy，直接加方案 A 最穩陣（兩個機制互相後備，冇額外成本）。

## 修訂後代碼（W-063 方案 A + S-223，供參考）

```css
/* v1.4.3: a pull-down at the top (iOS PWA rubber-band) dragged the whole page, sticky header included, and showed --bg
   between the navy status bar and the navy header. The root no longer bounces (Chrome, Safari 16+; some WebKit builds
   read body, so both are set); inner scrollers keep their own overscroll-behavior. */
html, body { overscroll-behavior-y: none; }
/* Where the root still bounces, WebKit fills the overhang with the canvas colour: make it navy. body keeps painting
   --bg over its own box (min-height: 100vh), so nothing navy shows at rest. Trade-off: a bottom pull-up on such
   devices also shows navy. */
html { background: var(--navy); }
/* Extra cover for engines that paint content above the document origin during the bounce. Expected, not verified on
   a device. */
body::before {
  content: '';
  position: absolute; left: 0; right: 0; bottom: 100%;
  height: 100vh;
  background: var(--navy);
  pointer-events: none;
}
```
