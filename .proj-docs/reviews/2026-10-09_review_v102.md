## 問題清單

### 🟡 W-036 — 320px en：「1.5 months」preset 爆出 chip

- **位置**：`css/screens/plan.css` L45–46（`.plan-stack .plan-presets` / `.plan-presets .chip`）
- **描述**：4 欄 `minmax(0, 1fr)` + `white-space: nowrap` + `padding-inline: var(--space-2)`。320px en 每格 content 58px，「1.5 months」要 67px（`scrollWidth 67 / clientWidth 58`），字溢出 chip 邊框（截圖可見「1.5 month」個 s 被截 / 壓住邊框）。舊 layout 係 flex-wrap，唔會截。
- **影響**：320px 裝置（iPhone SE 1st gen / 細 Android、大字設定）英文 UI 睇唔到完整選項；項目其他畫面一直守 320px。`plan-ui-test` `WIDTHS = [360, 375, 390, 400]` 冇 320，所以 `checkGoalLayout` 嘅 clipped assert 冇機會 fail。
- **方案 A（推薦）**：`@media (max-width: 340px) { .plan-presets .chip { padding-inline: 0; font-size: var(--fs-xs); } }`。Reviewer 實測：320px en / zh-HK 冇截字，chip 仍然一行、平分；≥ 360px 完全不變。
- **方案 B**：≤ 340px 改 `grid-template-columns: repeat(2, minmax(0, 1fr))`（2 × 2）。字號不變、tap 區更大，但違反「4 個一行」嘅字面要求，要問用戶。
- **測試**：`plan-ui-test` `WIDTHS` 加 320（`checkGoalLayout` 已有 clipped assert，加闊度就會守住）。

### 🟡 W-037 — 320px en：phase bar「Read + practise」被省略號截斷

- **位置**：`css/screens/plan.css` L84（`.plan-phase-bar span { … white-space: nowrap; overflow: hidden; text-overflow: ellipsis; }`）
- **描述**：等闊三段之後，320px en 第一段只得約 85px content，「Read + practise」顯示成「Read + prac…」。舊代碼 `min-width: max-content` 保證「a short phase still reads in full」— `js/screens/planSchedule.js` L62 新註解仍然咁講，但 320px 唔成立。用戶要求「names unchanged」。
- **影響**：320px 英文用戶睇唔到完整階段名；`checkScheduleFit` 嘅 `clipped` assert 本身寫得啱，只係 `WIDTHS` 冇 320。
- **方案 A（推薦）**：階段名容許換行：`.plan-phase-bar .plan-ph-name { white-space: normal; overflow-wrap: anywhere; }`（要用 `.plan-phase-bar .plan-ph-name` 先蓋得過 `.plan-phase-bar span` 嘅 specificity）。Reviewer 實測：320px en bar 高 41 → 55px，名兩行、日數第三行，冇截字；360px 以上同 zh-HK 不變（41px）。
- **方案 B**：≤ 340px phase bar 字號 `--fs-2xs`。三段高度不變，但 10px 白字粗體喺彩色底上可讀性差啲。
- **測試**：`plan-schedule-test` `WIDTHS` 加 320；`planSchedule.js` L62 註解改成符合實際（「a short phase wraps rather than clips」）。

### 🟢 S-116 — en 同一畫面「questions」/「Qs」混用

- **位置**：`locales/en.js` L287 `plan.schedule.strategy.learnPair`（`… ({facts} facts · {qs} questions)`）
- **描述**：用戶點名改 `orderCount` 同 task 行，但同一個 schedule 畫面嘅策略卡仍然寫「questions」，同下面次序卡「Qs」唔一致。
- **方案 A**：改「{qs} Qs」，同次序卡一致。**方案 B**：保留（句子式文案用全寫可讀性較好），喺 locale 註解寫明刻意。推薦：問用戶，傾向 B（唔擴大 scope）。

### 🟢 S-117 — 左欄 pill 字號 10px

- **位置**：`css/screens/plan.css` L125（`.plan-day-side .plan-pill { font-size: var(--fs-2xs); … }`）
- **描述**：Pill 基本字號係 `--fs-xs`（11px），移去 60px 左欄後縮到 10px；「Today 0%」都會拆兩行（截圖）。對比度冇問題，只係細字可讀性。
- **方案 A**：左欄 64px + 保持 `--fs-xs`（「Today 100%」兩行仍然入到）。**方案 B**：維持現狀。推薦：A，但屬視覺取捨，交用戶睇。

### 🟢 S-118 — 左欄闊度 60px 係 inline magic number

- **位置**：`css/screens/plan.css` L121（`.plan-day { grid-template-columns: 60px minmax(0, 1fr); … }`）
- **描述**：同一 commit 嘅 bar 闊度已經用咗具名 `--plan-chw-bar-w`，但 60px（pill 要入得到嘅限制值，`checkScheduleFit` 依賴佢）冇名。
- **方案 A**：`.plan-day { --plan-day-side-w: 60px; grid-template-columns: var(--plan-day-side-w) minmax(0, 1fr); }`。**方案 B**：維持（舊 48px 都係 inline）。推薦 A。
