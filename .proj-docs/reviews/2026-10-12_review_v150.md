### 🟡 Warning

#### W-064 — 0% 同 100% 嘅環狀態冇 test 守

- **位置**：`tests/plan-day-test.js` `checkHomeCard`（`full` 只 render `planHomePctHtml(PERCENT)` 讀 text / label）；`js/screens/planHome.js:162`（`${pct ? '' : ' empty'}`）
- **描述**：0% 有獨立分支（`.empty` → `visibility: hidden`，否則 round cap 會畫一粒 h0 點），但冇任何 assert；100% 只驗 ✓ 同 label，冇驗 `h4` band、`strokeDashoffset === '0'`、`.done` class。之後改 band / `PLAN_PCT_BAND_FROM` / empty 邏輯唔會有 test 紅燈。
- **影響**：用戶清單明列「0% / 100% / null edge cases」；null 有 test，0 / 100 只半覆蓋。
- **方案 A**：喺現有 `full` IIFE 旁邊加 `zero`：`planHomePctHtml(0)` → 驗 `.plan-home-ring-prog` class 含 `empty` + `h0`、text「0%」、label「Today's progress 0%」；`full` 加驗 class 含 `h4` 同 text 有 `.done`。純 helper，唔使造 0% / 100% 嘅日子。Trade-off：唔經 `renderPlanCard`，offset 唔驗。
- **方案 B**：用 `byId('planCard')` 真 render：`el.innerHTML = planHomePctHtml(0)` 然後跑 `renderPlanCard` 嗰段 offset 邏輯（或抽 `planHomeRingOffsets(el)` helper 俾兩邊用），驗 computed `visibility: hidden` + offset `100`；100% 驗 offset `0`。Trade-off：要抽 helper（少少改 production code）。
- **推薦**：A（最少改動；offset 已經喺主 case 驗咗公式）。

### 🟢 Suggestion

#### S-227 — 環 CSS 同日程環重複

- **位置**：`css/screens/plan.css:245–252` vs `:296–301`
- **描述**：`stroke-linecap` / `stroke-dasharray: 100` / `rotate(-90deg)` / `.empty` / `.h1–.h4` 兩套逐字一樣，只係 selector 唔同。之後改 G27 band 色或 empty 做法要改兩處。
- **方案 A**：合併 selector：`.plan-ring-prog, .plan-home-ring-prog { … }`、`.plan-ring-prog.h1, .plan-home-ring-prog.h1 { … }`（同上面 `.plan-mini i.hN, .plan-meter-fill.hN` 做法一致）；`transition` 留喺 `.plan-ring-prog` 自己。
- **方案 B**：加共用 class `.plan-arc`（兩個環嘅 prog 都加），band 規則寫一次。Trade-off：要改 `index.html` + `renderPlanRing` 嘅 `setAttribute('class', …)`。
- **推薦**：A（純 CSS，冇 markup 改動）。

#### S-228 — `stroke-width: 7` 同 `PLAN_HOME_RING_R = 28` 嘅關係冇寫

- **位置**：`css/screens/plan.css:244`、`js/screens/planHome.js:16–17`
- **描述**：環要 `R + stroke/2 ≤ BOX/2`（28 + 3.5 = 31.5 ≤ 32）先唔會被 viewBox 切；三個數分散喺 CSS / JS，冇註解講。改 stroke 去 10（日程環）就會切邊。
- **方案 A**：JS 常數註解加一句「R + stroke-width/2 (plan.css .plan-home-ring circle) must stay ≤ BOX/2」，CSS 註解互指。
- **方案 B**：新 token `--plan-home-ring-stroke: 7`（CSS 用），JS 改 `PLAN_HOME_RING_R = BOX/2 - STROKE/2 - 0.5` 由同一常數計。Trade-off：CSS / JS 仍然各自一個值。
- **推薦**：A。

#### S-229 — 讀屏「Today's progress」讀兩次

- **位置**：`js/screens/planHome.js:153`、`:160`
- **描述**：可見 `.plan-home-today-lbl`「Today's progress」讀一次，跟住下一步，然後環 `aria-label`「Today's progress 45%」再讀一次標題。唔錯，只係囉嗦（日程環冇可見重複標題）。
- **方案 A**：環 `aria-label` 只放 %（「45%」）。Trade-off：單獨 focus / 瀏覽環時冇 context。
- **方案 B**：label span 加 `id`，環用 `aria-labelledby="<lblId> <pctId>"`（pct 放 visually-hidden span 或 `<title>`）。Trade-off：卡要有唯一 id。
- **推薦**：記錄即可；要改就 A（label 喺正上面，context 已經夠）。

#### S-230 — test 同實現同一 commit（TDD 記錄）

- **位置**：`54b402d`
- **描述**：冇獨立紅燈 commit。Reviewer 用 `b841880` app 檔 + 新 test 跑 → `PLAN-DAY FAIL`（`page.evaluate: TypeError … reading 'textContent'`），紅燈成立；不過係 crash 唔係 assert message。
- **方案 A**：下次分開 test commit。**方案 B**：test 用 `q(...)?.textContent` 令舊版失敗時出 assert 訊息而唔係 TypeError。
- **推薦**：記錄（A）。
