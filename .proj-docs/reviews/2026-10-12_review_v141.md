## 問題清單

### 🟢 S-218 — `upgrade-test` `dump()` 一律過濾 seed key，升級路徑寫咗語言 / 字號都睇唔到

- **位置**：`tests/upgrade-test.js:65-67`（`dump`），影響 `oppositeMix`「storage untouched」（約 442 行）同真 SW 升級 v0.57 → 而家「only new key is the marker」/「another reload: storage unchanged」（約 511–529 行）
- **描述**：Seed 令每個 page 都有 `lifeuk.uiLang` / `lifeuk.fontSize`，所以 `dump()` 將呢兩個 key 由所有比較拎走。之前呢幾個 assertion 會捉到「升級 / migration 路徑寫咗 `lifeuk.uiLang` / `lifeuk.fontSize`」；而家唔會。`default-settings-test` 只驗而家 shell 首次開唔寫，冇驗 migration / SW 升級路徑。
- **影響**：低。而家 code 冇寫呢兩個 key 嘅升級路徑；不過 v1.4.1 正正係「冇存值嘅舊用戶跟新預設」，日後如果有人喺升級時「幫用戶寫低預設」，會將佢哋鎖死喺某個預設，test 會靜靜 pass。
- **方案 A**（推薦）：真 SW 升級 case 喺 `seed()` 之前 `sessionStorage.setItem(NO_SEED_SS, '1')`，嗰個 case 用一個唔過濾嘅 `dump`，`extra` 照舊只准 `MARKER`。好處：直接驗「升級後唔寫語言 / 字號」；代價：嗰個 case 嘅 `captureUI` 只比較掌握數，唔受語言影響，所以冇其他改動。
- **方案 B**：`dump()` 唔過濾，改做 assert seed key 嘅值仍然係 `LEGACY_DEFAULTS`（被改就 fail），再喺比較時拎走。好處：所有 case 一次過守住覆寫；代價：仍然驗唔到「冇值時寫入」（因為 seed 已經寫咗）。

### 🟢 S-219 — HANDOFF `i18n-test` 行仲寫「reload 當 en」

- **位置**：`HANDOFF.md` 測試表 `i18n-test.js` 嗰行：「存咗冇 locale 嘅語言 reload 當 en、存咗 `constructor` / `__proto__` reload 當 en 而冇 warning、`setLang('toString')` 唔理」
- **描述**：`d7dde3e` 已經將呢幾個 assertion 改做 zh-HK（`INITIAL_LANG`），HANDOFF 其他地方（i18n 段、`lifeuk.uiLang` 行、v1.4.1 版本行）都改咗，淨係呢行冇跟。
- **方案 A**（推薦）：改做「reload 當首次預設語言（v1.4.1 起 zh-HK）」，再補一句「suite 用 `legacy-defaults` 種 en + 細字」。
- **方案 B**：只加「（v1.4.1 起 zh-HK）」括號。

### 🟢 S-220 — `<html lang="zh-HK">` 但 `<title>` / meta description 係英文（記錄，唔扣分）

- **位置**：`index.html:2`、`:7`、`:10`、`:11`
- **描述**：JS 未行（或者冇 JS 嘅讀取者，例如連結預覽、搜尋引擎）時，文件語言標 zh-HK，但 `<title>` / `meta description` / `apple-mobile-web-app-title` 係英文 literal（HANDOFF「i18n」寫明係刻意留俾 no-JS 讀取者）。JS 行咗之後 `applyDocumentI18n()` 會換成中文，所以用戶睇到嘅冇問題。
- **方案 A**（推薦）：維持現狀，喺 HANDOFF `index.html` 行記低「v1.4.1 起 `<html lang>` 同 no-JS 英文 literal 唔一致，係取捨」。
- **方案 B**：將 `<title>` / meta 改做中文 literal，同 `lang` 一致；代價係英文 no-JS 讀取者（例如英文連結預覽）見中文。屬產品決定，要問用戶。

### 🟢 S-221 — Seed wrapper 令 `page.close()` 唔再關佢個 context

- **位置**：`tests/legacy-defaults.js:22-26`
- **描述**：Playwright `browser.newPage()` 開嘅 context 屬於嗰個 page，`page.close()` 會一齊關。Wrapper 改做 `newContext()` + `ctx.newPage()`，context 就唔屬於 page，`pg.close()` 之後 context 留到 `b.close()`。`upgrade-test` 開十幾個 page，記憶體會累積；而家冇 fail，只係 test 行為同原本唔一樣。
- **方案 A**（推薦）：`browser.newPage = async (...args) => { const ctx = await browser.newContext(...args); const pg = await ctx.newPage(); pg.once('close', () => ctx.close().catch(() => {})); return pg; };`
- **方案 B**：維持現狀，喺 helper 註解寫明「page.close() 唔會關 context」。

## 修訂後代碼（S-218 / S-221 方案 A 示範，test only）

```js
// tests/legacy-defaults.js — S-221: a page from browser.newPage() owns its context again
function seedLegacyDefaults(browser) {
  const newContext = browser.newContext.bind(browser);
  browser.newContext = async (...args) => seedContext(await newContext(...args));
  browser.newPage = async (...args) => {
    const ctx = await browser.newContext(...args);
    const pg = await ctx.newPage();
    pg.once('close', () => ctx.close().catch(() => {})); // same lifetime as Playwright's own browser.newPage()
    return pg;
  };
  return browser;
}

// tests/upgrade-test.js — S-218: the real SW upgrade runs without the legacy seed, so the dump keeps every key
const dumpAll = pg => pg.evaluate(() => Object.fromEntries(Object.keys(localStorage).sort().map(k => [k, localStorage.getItem(k)])));
// in the SW upgrade case, before seed(pg, { ...LEGACY, ...FOREIGN }):
await pg.evaluate(ss => sessionStorage.setItem(ss, '1'), NO_SEED_SS);
// …and use dumpAll(pg) for ls57 / ls / "another reload" / after, so `extra` still has to be exactly [MARKER]
```
