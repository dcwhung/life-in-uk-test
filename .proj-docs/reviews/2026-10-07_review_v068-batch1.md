### sw-test 偶發失敗：量度、根因、結論

**量度**：喺 `67d275a` 連續跑 `node tests/sw-test.js` **15 次**，fail **3 次（20%）**。三次嘅 diag 一模一樣：

```
diag: version bump did not settle — {"workers":{"installing":null,"waiting":null,"active":"activated"},"caches":["other-app","lifeuk-v0.67"]}
FAIL: version bump in config.js alone installs a new cache
```

即係話新 worker 由頭到尾冇 install 過。`reg.update()` 試咗 40 次（大約 10 秒）都認為 `sw.js` 同 `config.js` 冇變，所以 fail 嘅係**第一個** assert，唔係 S-063 新加嘅 `assert(poll.settled)`。

**根因（已用實驗證實）**：`tests/pages-server.js` 用 Python `http.server`，佢會送 `Last-Modified`，亦會處理 `If-Modified-Since`。兩者都只精確到**秒**。sw-test 先將 app 複製去 temp dir，然後喺大約 1–2 秒之內寫入 bump 咗嘅 `config.js`。如果寫入同複製喺**同一秒**，mtime 去到秒數係一樣嘅，update check 攞 `config.js` 就會收到 **304 Not Modified**，Chromium 判斷 imported script 冇變，之後 40 次都一樣。

| 實驗 | 次數 | 結果 |
|---|---|---|
| 原版 + 探針（記錄寫入時間同複製 mtime 係咪同一秒） | 20 | 1 次 fail，正正係 `sameSecond=true` 嗰次；其餘 19 次 `sameSecond=false`，全部 pass |
| 寫入之後 `fs.utimesSync(configPath, now+2, now+2)` | 15 | **15 / 15 pass** |

（實驗用嘅臨時 script 已經刪咗，冇留喺任何 checkout。）

**結論**：
- **要喺呢個 PR 修**（W-017）。呢個係測試 harness 嘅 race，唔係產品 bug：GitHub Pages 部署同之前一次 fetch 相隔遠多過 1 秒，而且有 ETag。不過佢令 hard gate「Tests 全綠」有大約 20% 機會假紅，每次都要人手重跑，久而久之大家會唔再信個 gate。修正只係一行、淨改 test、已經驗證過。
- **S-063 嘅 `assert(poll.settled)` 保留**。佢冇增加失敗率（觀察到嘅 fail 全部喺佢前面已經 fail 咗），反而補咗一個以前會靜靜 pass 嘅情況（cache 啱但 worker 仲 waiting）。

### 發現

#### 🟡 W-017 — sw-test version bump 同 Python `If-Modified-Since` 秒級精度有 race（20% 假紅）
- **位置**：`tests/sw-test.js` `checkVersionBump()`，`fs.writeFileSync(configPath, …)` 之後
- **影響**：`run-all.sh` 大約每 5 次有 1 次假 fail（今日 developer 遇過兩次，我量到 3/15）
- **方案 A**：寫完之後將 mtime 推前 2 秒，保證同第一次 fetch 嗰秒唔同：
  ```js
  fs.writeFileSync(configPath, …);
  // http.server compares If-Modified-Since to the second: a same-second write would be answered 304 (unchanged)
  const BUMP_MTIME_AHEAD_S = 2;
  const bumpAt = Date.now() / 1000 + BUMP_MTIME_AHEAD_S;
  fs.utimesSync(configPath, bumpAt, bumpAt);
  ```
  好處：一行修正，已經驗證 15/15。壞處：只修 sw-test 呢個位。
- **方案 B**：`pages-server.js` 唔再處理 conditional request（例如 `send_head` 剷走 `If-Modified-Since`），或者改送 ETag。好處：所有用呢個 server 嘅 test 都受惠。壞處：改咗「模仿 GitHub Pages」嘅 server 行為，upgrade-test 有可能依賴 304，要逐個驗。
- **推薦**：A。常數放 `sw-test.js` 頂部，同 `SW_SETTLE_*` 放埋一齊。

#### 🟢 S-067 — S-037 `layerCode` 冇 blank template literal
- **位置**：`tests/structure-test.js` `layerCode` / `stripComments`
- **描述**：`layerCode` 只 blank 單引號同雙引號字串，template literal 冇 blank（為咗保留 `${}`）。如果 template 入面有 `//`，而且前面唔係 `:`（例如 `` `a // b` ``），之後嗰行嘅 code 會當咗註解剷走。如果 template 入面有 `/*`，甚至可以食走幾行。而家 `js/components/` 冇呢種寫法，所以只係潛在漏報。
- **方案 A**：加一個 sample `` { code: 'const s = `a // b`; renderStudy();', hit: true } `` 記錄呢個已知限制，test 預期係 miss 或者 hit 都得，但要寫清楚。
- **方案 B**：template literal 冇 `${}` 嘅部分照樣 blank，只留 `${…}` 入面嘅表達式。
- **推薦**：A（可選）。
