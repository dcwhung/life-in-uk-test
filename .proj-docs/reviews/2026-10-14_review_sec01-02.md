## 背景

`/api/track` 冇登入，`Origin` 檢查只係 filter。審計 SEC-01 / SEC-02：有人灌 request 可以令 Upstash 配額燒晒、數字俾人灌大，而 owner 喺 dashboard 睇唔出。

今次 branch 做嘅嘢：
- **每日 budget**：`INCR lifeuk:budget:<UTC 日>`，超過 `DAILY_REQUEST_BUDGET`（4000）照回 204 但唔計 event
- **AU-031**：budget key 2 日 expire（當日第一個 request 喺 event pipeline 設）
- **SEC-01**：封頂日寫 `lifeuk:capped:<日>`（冇 TTL），`/api/stats` 回 `capped`，`stats.html` 顯示提示
- **SEC-02**：warm instance 記住封頂日（`budgetSpentOn`），同日之後直接 204 唔 call Redis
- **Firewall**：per-IP rate limit 要 owner 喺 Vercel dashboard 手動設（`.proj-docs/deploys/2026-10-14_vercel-firewall-track.md`）

## 第 1 輪（`ab59da4`）：⚠️ warn 86/100

### 🟡 W-400：capped 記號只靠越線嗰個 request
- **位置**：`api/track.js`
- **問題**：只有 `used === DAILY_REQUEST_BUDGET + 1` 嗰個 request 寫 `lifeuk:capped:<日>`。如果佢嘅 `SET` 失敗，或者 INCR 喺 Redis 行咗但回覆冇咗（timeout → 502），嗰日就永遠冇記號，dashboard 唔會提示數字偏低。
- **處理**：任何超過上限嘅 request 都 `SET … 1 NX`（NX 保留第一次寫入）；有 SEC-02 短路，每個 instance 每日只行一次。Fake Redis 學識 NX 同兩種故障（`error` / `lost`）。

### 🟡 W-401：Firewall 教學計錯 per-IP 上限
- **位置**：`.proj-docs/deploys/2026-10-14_vercel-firewall-track.md`
- **問題**：教學話每 60 秒 10 個「單一 IP 灌唔滿 budget」。實際 10 × 60 × 24 = 14,400 > 4000，一個 IP 約 6.7 小時就灌得滿。
- **處理**：保留 10 / 分鐘擋爆發，另加每小時 100（一日 2,400 < 4000）；冇 1 小時 window 就改每 60 秒 2 個（2,880 < 4000）。Vercel 有冇 1 小時 window 未核實。

### 🟢 Suggestion
| ID | 問題 |
|---|---|
| S-300 | budget key 嘅 TTL 只喺當日第一個 request 設；嗰個 `EXPIRE` 失敗，封頂日嘅 budget key 就永遠唔 expire。建議 capped pipeline 順手再 `EXPIRE` |
| S-301 | track test 共用一個 `require` 咗嘅 `api/track.js`，SEC-02 module state（`budgetSpentOn`）會由一個 check 漏去下一個，結果視乎執行次序 |
| S-302 | `#cappedNote` 出現時 screen reader 唔會讀；應該係 `role="status"`（禮貌通知，唔係 alert） |
| S-303 | Firewall 教學引用 dashboard 提示嘅字眼同 `locales/stats.js` 唔一樣（「到咗」vs「去到」） |
