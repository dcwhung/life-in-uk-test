### (1) `u` flag 有冇改變語義

理論分析：
- `[(,=:[!&|?;{}*%<>~^]` 入面冇 escape 嘅 `[`：只有 `v` flag 先會拒絕，`u` mode 下照樣當 literal `[`。
- `\s`：有冇 `u` 都係 Unicode whitespace 集合，冇分別。
- `\w`：`u` mode 但冇 `i` 時仍然係 ASCII `[A-Za-z0-9_]`。
- 冇 identity escape（`u` mode 會拒絕 `\-` 之類），冇 `\b`、冇 `i` flag，所以冇 case-folding 差異。
- Lookbehind 喺 `u` mode 按 code point 回溯：astral 字元（例如 emoji）會當一個字元睇；新舊 regex 對 `"😀in "` 嘅結果一樣（都係 true，emoji 本身唔係 identifier）。

差分測試（舊 regex 對比新 regex，用 `layerCode` 全流程）：
- 70 個 prefix（`''`、`return`、`y.return `、`a?.in `、`a?.of`、`x$of `、`$in `、`o. of `、`o.\nof `、`''(`、`i++ `、`i-- `、`a + +`、`b - `、`b -- `、`f(x) `、`a[0] `、`arr[`、全部 keyword、全部 punctuation 等）：**只有 8 個結果唔同**，全部係預期中嘅（`this.#of`、`#in`、`éin`、`ñof`、`Ωreturn`、`中of`、`ªin`、`ʰin`）。
- 24 個 `layerCode` edge sample：包括上次 review 加 QA 嘅 `return /x/`、`y.return / 2`、`a?.in / 2`、`x$of / 2`、`$in / 2`、`o. of / 2`、`${/'/…}`、`i++ / 2`、`a + +/x/`、`b - /re/`、`typeof /x/`、`k of /x/`、`k in /x/`、`await /x/`、`/[(,=]x/`、`/[/\`]/`、`a ? /x/ :`、`[/x/]`。舊 regex 啱嘅，新 regex 全部都啱；新增修正咗 `#in`、`ñof`、`中of`、`Ωreturn`。
- 3 個 mutation（喺 worktree 重做）：剔走 `#` 令 #private sample 紅；剔走 `\p{L}` 令 non-ASCII sample 紅；**剔走 `u` flag**（`\p{L}` 變返 literal `p{L}`）令 non-ASCII sample 紅。所以 `u` flag 本身都有 test pin 住。
- 另一個觀察（唔開 item）：最初兩次 ad-hoc `node -e` probe 印出 `N.test("a + +") === false`，但之後 105 次重跑（包括同一句 command、獨立 script、20000 次 tier-up loop、`--regexp-interpret-all`）全部都係 `true`，同舊 regex 一致，`a + +/renderStudy/` sample 亦 pass。重現唔到，應該係我自己 probe 出錯，唔當係 regex 問題。

### 🟢 Suggestion

#### S-091 — REGEX_AFTER keyword lookbehind 用 `\p{L}`，未涵蓋全部 ID_Continue

- **位置**：`tests/structure-test.js:77`
- **描述**：lookbehind `(?<![\w$#\p{L}]|\.\s*)` 會將 `x́in`、`x٣in`、`x‍in`、`Ⅻin`、`x·in` 嘅尾段當成 keyword `in` / `of`，跟住個 `/` 會被當成 regex 開頭，可能會吞走後面嘅 code（即係 guard false negative）。
- **影響**：codebase 0 影響（冇呢類 identifier）。純理論完整性問題。
- **方案 A**：改用 `(?<![$#\p{ID_Continue}‌‍]|\.\s*)`（`\p{ID_Continue}` 已經包括 `\w`），加 1 個 sample，例如 `x = x٣in / 2; renderStudy(); y = z / 3;`。我喺 worktree 驗證過：31 個 sample 全 pass，components guard 0 hit，24/24 檔案輸出不變，上表 5 個 case 全部改正。
  - Trade-off：regex 長少少，`\p{ID_Continue}` 冇 `\p{L}` 咁多人識，要喺註解講清楚。
- **方案 B**：唔改，喺 S-090 註解加一句「Mn / Nd 等其他 ID_Continue 字元唔處理（codebase 冇用）」。
  - Trade-off：零成本，但定義仍然唔完整。
- **推薦**：B 或者遲啲先做 A。下次再改 structure-test 時順手用 A 收尾就得，唔 block 今次 merge。
