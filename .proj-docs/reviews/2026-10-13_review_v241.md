### 🟡 W-085 — 320×568 手機：大部分組失去一屏高版面（交用戶決定）

- **位置**：`data/memo.js`（61 組 hook）× `js/screens/memo.js` `memoFitPhone` → `js/components/fit.js` `fitPhoneScreen`（C-007）、`css/components/fit.css` `--fit-phone-min-panel: calc(10 * var(--fs-xl))`
- **描述**：`main` 只有 15 組有 hook；而家 61 組都有，hook 框固定喺 panel 上面，320×568 大字時 hook 高 166–259px，panel 剩唔夠 `--fit-phone-min-panel`，`fitPhoneScreen` 就退返捲動頁。en large 15 → 58 / 62 組，zh large 15 → 54 / 62，en small 9 → 31，360×640 en large 2 → 12。375×667 或以上冇影響。
- **影響**：功能冇壞（C-007 fallback 照設計運作，`phone-memo-test` 嘅 zh 短手機 check 確認 panel ≥ 120px 或者捲動、所有掣撳得到）。UX 方面，320 寬大字時 mockup rev 6 嘅「hook 固定、note panel 自己捲、開始掣喺底」幾乎冇咗：要成頁捲 320–875px 先見到「開始測驗」，note fade 都冇。受影響嘅係 iPhone SE 第一代 / 5s 呢類 320px 機，或者細 Android + 大字；`main` 已經有 15 組係咁，所以唔係新類型嘅問題，只係多咗好多。
- **方案 A（接受）**：保留現狀，HANDOFF / C-007 記錄「320×568 大字大部分組捲動」。成本 0；捲動頁本身可用，所有掣撳得到。
- **方案 B（≤ 360px 細 hook 字）**：`@media (max-width: 360px)` `.memo-hook span { font-size: var(--fs-sm) }`（同埋 / 或者收窄 `.memo-hook` padding）。估計 hook 矮 15–20%，可以救返部分 zh small / en small，但 en large 嘅 hook（中位 189px）仍然大過可用空間，58 組唔會跌好多。改動細，但大字用戶揀大字就係要大字，同 `fontsize` 設定有衝突。
- **方案 C（可摺 hook）**：手機 fallback 時 hook 用 `<details open>`（或者第二行之後摺埋，撳「顯示全部」），摺埋就變返一屏高。最有效，但係新互動，要 mockup / 用戶批，`memo-test` / `phone-memo-test` 要加 case；仲要諗清楚記憶鈎係呢頁嘅主角，預設摺埋會削弱「睇」呢一步。
- **推薦**：A（接受），然後問用戶有冇 320px 機嘅實際投訴；要改嘅話先試 B 量數字，C 留俾有 mockup 先做。

### 🟡 W-086 — merge 將 `tests/memo-test.js` 嘅 `\u` escape 改返 literal 隱形字元

- **位置**：`tests/memo-test.js` CUI-0044 幾何 check（`page.evaluate` 入面嘅兩條 token regex 同兩組 `.replace(…)`，第 423–424、431、440 行）：**9 個 literal U+00A0、4 個 literal U+2060**（`46121e4` 同 `e5d4641` 兩邊都係 0）
- **描述**：`e6b29aa`（CUI-0044）特登將 test 嘅 U+00A0 / U+2060 改做 `\u00a0` / `\u2060`（commit 標題：「tests spell U+00A0 / U+2060 as escapes」）。今次重寫呢段時變返 literal 字元：regex 嘅「空格或 NBSP」字元組睇落係兩個空格，`replace(NBSP, ' ')` 睇落係換空格做空格，範圍嘅「–」後面跟住一個睇唔到嘅 U+2060。行為一樣（test PASS），但係睇唔到。**可能成因**：寫檔工具會將 `\uXXXX` 轉做字元（reviewer 寫呢份報告時都中咗，已改返），所以要用 `grep -P` 或者 Python 驗，唔可以靠肉眼。
- **影響**：之後有人「整理」呢幾行（例如 editor 自動 trim、或者覺得 `[  ]` 重複刪一個），check 就會靜靜咁變弱或者錯，review 都好難睇出；同同一個檔其他地方（第 405、409、459、464 行用 `\u`）唔一致。
- **方案 A（推薦）**：嗰幾行改返 `\u00a0` / `\u2060`（regex literal 入面 `\u00a0` 一樣用得），之後 `LC_ALL=C.UTF-8 grep -nP '[\x{a0}\x{2060}]' tests/memo-test.js`（要 UTF-8 locale，否則 grep 報 code point too large）應該冇結果。
- **方案 B**：喺 `structure-test`（或者新嘅細 check）禁止 `js/`、`tests/` 有 literal U+00A0 / U+2060 / U+202F，一勞永逸。成本多少少，但可以防 S-271 / CUI-0044 呢類改動再犯。
