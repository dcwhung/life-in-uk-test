### Suggestion

#### S-099 — time up over **Submit** modal 冇 stray-Enter regression test
- **位置：** `tests/examtools-test.js` W-024 block（約 L104–110）
- **描述：** S-098 case 只 cover Leave modal。Submit modal 版本（W-024 block）時間到之後冇撳 Enter。
- **影響：** Probe P2：如果將來有人改 `showScreen` / `closeConfirm` 令 blur 失效，Submit modal 路徑會 double-submit（`finishExam` 2 次）兼清走 time-up note，現有 suite 唔會紅（W-024 assert 只喺時間到嗰刻檢查）。而 Leave 版本喺 fresh page 用 click 開 modal 時，冇 fix 都只係間歇紅（P3'），Submit 版本係 deterministic（3/3）。
- **方案 A：** W-024 block 最後加：
  ```js
  await pg.keyboard.press('Enter');
  assert(await active('screenResult') && !(await modalOpen()) && await vis('#resultTimeUp'), 'W-024 / S-098: a stray Enter after time up does not reopen Submit');
  ```
  Trade-off：一行，最平；mutation 下必紅。
- **方案 B：** 同時將 S-098 case 改用鍵盤開 Leave modal（`pg.focus('#screenQuiz .back-btn'); pg.keyboard.press('Enter')`），令佢喺獨立跑時都 deterministic。Trade-off：多改一行；而家喺 suite 入面已經 5/5 紅，收益細啲。
- **推薦：** A（必做），B 可選。

#### S-100 — 轉 screen 後 focus 落 body，冇移去新 screen（pre-existing，a11y）
- **位置：** `js/core/utils.js` `showScreen`
- **描述：** 而家（同 v0.69 前一樣）轉 screen 後 focus 喺 body；keyboard 用戶要由頁頂 Tab 起，screen reader 冇「已去 Results」嘅提示。
- **影響：** 低；唔係 regression，呢個 delta 只係令行為一致。
- **方案 A：** 每個 screen 嘅標題加 `tabindex="-1"`，`showScreen` 喺 blur 之後 `focus({ preventScroll: true })` 新 screen 標題。Trade-off：要逐個 screen 揀 heading，要核對 doubletap-test / CUI-0010 等 focus 相關 test；同 Study ↩ Back 嘅 scroll 還原要用 `preventScroll`。
- **方案 B：** 加一個 `aria-live="polite"` 區域，`showScreen` 寫入 screen 名。Trade-off：唔郁 focus，風險細，但 keyboard 用戶仍要由頂 Tab。
- **推薦：** 放 backlog，下個 a11y pass 先做；唔 block 今次。
