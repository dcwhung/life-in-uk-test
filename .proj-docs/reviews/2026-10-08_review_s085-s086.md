### 🟢 S-088 — `REGEX_AFTER` keyword lookbehind 漏咗 `$` 同「`.` + 空白」
- **位置**：`tests/structure-test.js:75`（`REGEX_AFTER`）
- **描述**：`(?<!\.)\b(?:…|in|of|…)` 靠 `\b` 判斷 keyword 開頭，但 `$` 唔係 `\w`，所以 `$in` 入面 `$` 同 `i` 之間有 `\b`，`$in` 會被當做 keyword `in`。`x = $in / 2; renderStudy(); y = z / 3;` → `x = $in '' 3;`，**`renderStudy()` 漏報**。同一個問題亦影響 `$return`、`$case` 等（S-085 之前已經存在）。另外 `(?<!\.)` 只睇緊貼嘅一個字元，`o. of / 2` 都會漏報。
- **影響**：只會漏報唔會假紅；要同一行有第二個 `/` 先出事；`js/` 而家冇呢類寫法。好少見。
- **方案 A**（推薦）：lookbehind 改成 `(?<![\w$]|\.\s*)(?:return|…|await)\b`（V8 支援可變長度 lookbehind），再加 1 個 sample：`x = $in / 2; renderStudy(); y = z / 3;`（`hit: true`）。Trade-off：一行改動，準確度更高；regex 再長少少。
- **方案 B**：唔改 code，喺 `REGEX_AFTER` 註解列明「`$` 開頭嘅 keyword 名同 `. of` 未處理」。Trade-off：零風險，但保留已知缺口。
- **推薦**：A（細改，而且順手修埋 S-085 之前已有嘅 `$return` 等）。
- **扣分**：正確性 −1

### 🟢 S-089 — 冇 sample 守住 `-` 做 binary operator 之後嘅 regex
- **位置**：`tests/structure-test.js` `LAYER_SAMPLES`
- **描述**：Mutation S4（`REGEX_AFTER` 唔再當 `-` 係 operator）之後 26 個 sample 全部仍然綠。新 guard 只有 `a = b + /renderStudy/.source;`，冇對應嘅 `-` 版本，所以將來改 `(?<![+-])[+-]` 時改壞 `-` 唔會有 test 發現。

- **方案 A**（推薦）：加 1 個 sample：`{ code: 'a = b - /renderStudy/.source.length;', hit: false, why: 'a name inside a regex after a binary -' }`。Trade-off：一行，對稱 `+` guard。

- **推薦**：A。
- **扣分**：測試覆蓋 −1

// S-074: a / opens a regex literal where a value is expected: at the start, after an operator / opening
// punctuation, or after a keyword such as return (after a name, a number, ) or ] it is a division)
// S-085: postfix ++ / -- and a property named in / of (o.in) end a value, so a / after them is a division
