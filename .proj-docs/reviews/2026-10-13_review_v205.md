## 問題清單

### 🟡 W-071 — CUI-0037 號碼 + APP_VERSION 次序同未 merge 嘅 `loving-cannon` branch 撞

- **位置**：`.tickets/completed/0001-0200/CUI-0037.md`、`js/core/config.js:5`（`APP_VERSION = '2.0.5'`）；對方 `origin/claude/loving-cannon-gb40bk`（`.tickets/pending/0001-0200/CUI-0037.md`「two-phase plan / goal limits」，由 CUI-0030 改號；`APP_VERSION = '2.1.0'`；review `2026-10-13_review_v210-cui37.md` 用 W-382、S-250–S-252）
- **描述**：兩條 branch 都由 `main` 分出、都未 merge。(1) 兩張唔同嘅 ticket 都叫 CUI-0037（檔案一個喺 `completed/`、一個喺 `pending/`，git 唔會 conflict，所以 merge 時好易冇人發現）。(2) 如果 `loving-cannon` 先 merge，`main` 會係 2.1.0，再 merge 呢條就會將 `APP_VERSION` 降返 2.0.5（SW cache 名仍唔同所以功能上會更新，但版本號倒退、HANDOFF 版本表亂序）。(3) 對方 S-250–S-252 同 `2026-10-13_review_v203.md` 嘅 S-250–S-253 撞（唔係今次範圍，順手記錄）。
- **影響**：ticket / commit message / review 引用 CUI-0037 會指去兩件事；版本號可能倒退。
- **方案 A**：而家喺 `.proj-docs/index.md` 頂部加一段「再撞號」記錄（同之前幾次一樣），講明後 merge 入 `main` 嗰條要將 ticket 改號（CUI-0038）同版本升到高過 `main`（例如 2.1.1）。Trade-off：唔使改 commit，但要靠人記得。
- **方案 B**：呢條 branch 即刻將 ticket 改號 CUI-0038、版本改 2.1.1。Trade-off：如果呢條先 merge，就白改咗號 / 版本跳咗一格；commit message 仍寫 CUI-0037。
- **推薦**：A —— 邊條先 merge 未知；merge 第二條嗰陣先改號 + 升版本，同 v2.0.3 / v2.0.4 嗰次處理一致。

### 🟢 S-254 — `.my-tile .t-icon` 嘅 `font-size` / `font-weight` 變咗死碼

- **位置**：`css/screens/home.css:127`（`font-size: var(--fs-lg); font-weight: 900;`）
- **描述**：呢兩個 property 只係為咗以前嘅「✗」字；而家兩粒 tile 嘅 icon 都係 SVG（有固定 px 大細），冇字受影響。
- **方案 A**：刪走兩個 property。Trade-off：最乾淨；如果將來有人再放字入去會冇樣式（但規則本身禁止 glyph）。
- **方案 B**：保留，加註解。Trade-off：零風險但留低誤導。
- **推薦**：A。

### 🟢 S-255 — `LINE_ICON_PATHS.cross` 同 `close` path 一模一樣

- **位置**：`js/components/icons.js:33`、`:38`
- **描述**：分開名有道理（語意：「答錯」唔係「關閉」，註解有寫），但 path 數據抄咗一次；將來改 `close` 筆畫（例如縮細）時 `cross` 唔會跟。
- **方案 A**：抽 `const X_STROKES = ['M6.5 6.5l11 11', 'M17.5 6.5l-11 11'];`，`close: X_STROKES, cross: X_STROKES`。Trade-off：一個來源；但兩者其實可能想各自演變。
- **方案 B**：保持現狀（兩個語意 icon 各自獨立，日後可以分開調）。Trade-off：重複兩行。
- **推薦**：B 都接受（我個人傾向 B，因為分開名就係為咗可以各自調）；如果團隊重視 DRY 就 A。只記錄，唔使改。
