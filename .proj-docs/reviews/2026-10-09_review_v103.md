### 🟡 W-038 — `plan-schedule-test.js`：`checkScheduleFit`（51 行）同 `checkDayList`（97 行）超過 30 行

- **位置**：`tests/plan-schedule-test.js` `checkScheduleFit`（L469–519，main 時 23 行）、`checkDayList`（L151–247，main 時 62 行，今次再加 35 行）
- **描述**：v1.0.3 將「寬字體 Today pill」、「Reset plan 全闊行」塞入 `checkScheduleFit`，將 bullet list / 顏色 / 對比度三組 assert 塞入 `checkDayList`。每組都係獨立關注點。
- **影響**：項目規則 function ≤ 30 行（v068 review 已套用落 test helper）；一個 assert fail 時要喺 50–100 行入面搵係邊組，`checkDayList` 嘅 `pg.evaluate` 已經回傳 17 個欄位。
- **方案 A（推薦）**：按關注點抽 helper，`checkScheduleFit` 只負責調用：
  ```js
  async function checkScheduleFit(pg, where) {
    await checkPhaseAndPill(pg, where);        // 舊 23 行嘅 evaluate + 3 個 assert
    await checkTodayPillWideFont(pg, where);   // v1.0.3 Arial / Helvetica × 1.1
    await checkOrderBars(pg, where);
    await checkPlanResetRow(pg, where);        // 「↺ Reset plan」全闊行
  }
  ```
  `checkDayList` 同樣抽 `dayListNotes(pg)`（evaluate）、`checkDayRemarks(pg, notes)`（list / 顏色）、`checkRemarksContrast(pg)`（對比度）。純搬 code，assert 文字不變。
- **方案 B**：喺 `main()` 嘅 check list 直接登記多幾個獨立 check（`checkDayRemarks`、`checkRemarksContrast`），每個自己 seed / open schedule。更獨立，但每個 check 多一次 `fresh + seedPlan`（約 +1 秒），而且要處理 `checkWidths` 入面嘅 per-width 調用。
- **推薦**：A（零行為改動，test 時間不變）。
