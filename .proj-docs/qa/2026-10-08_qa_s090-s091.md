## Section B — S-091（b752df8）`[$#\p{ID_Continue}]`（獨立 review + QA）

### Claim 核實
```
$ node -e 'console.log(process.versions.unicode, /\p{ID_Continue}/u.test("‌"), /\p{ID_Continue}/u.test("‍"), ...)'
16.0 true true true true false false      # ZWNJ ZWJ U+0301 U+0663 → true；$ # → false
```
- Node 22（Unicode 16.0）嘅 `\p{ID_Continue}` 確實包 ZWNJ / ZWJ ✅。`$`、`#` 唔喺 ID_Continue，所以 lookbehind 明確加返係必要 ✅（M3 剔 `$` → `$in` sample 紅）
- ASCII 部分 ID_Continue = `[0-9A-Za-z_]`，即 `\w` —— 對 ASCII 行為同 S-088 / S-090 完全一樣

### `\p{ID_Continue}` 會唔會錯包「非 identifier 但可以喺 keyword 前出現」嘅字元？
全 code point 掃描（0–0x10FFFF）：ID_Continue ∩（JS 空白 `\s`/U+FEFF ∪ ASCII 非 word 字元 ∪ `Pattern_Syntax` ∪ `Pattern_White_Space`）= **0 個**。
ID_Continue 但唔屬 L/M/N/Pc 嘅只有 U+00B7、U+0387、U+200C、U+200D、U+2118、U+212E、U+309B、U+309C、U+30FB、U+FF65 —— 全部喺 JS 只可以作 identifier part，唔係 operator / punctuator / whitespace。JS 所有 punctuator 都係 ASCII 非 word，所以冇任何合法 token 會被誤當 identifier 尾 ✅。
另外直接測咗合法 JS 空白（U+00A0、U+FEFF、U+3000、U+2028）喺 keyword 前：keyword 仍然認到，regex 照樣被隱藏 ✅。

### 觀察：ZWJ sample 依賴 Node 嘅 Unicode 版本
ZWNJ / ZWJ 由 Unicode 15.1 先入 ID_Continue。Repo 冇 `package.json` engines / `.nvmrc` / CI pin Node 版本；如果喺 `process.versions.unicode` < 15.1 嘅 Node 跑，`a name with a ZWJ` sample 會紅（係 test 環境假紅，唔係漏 bug）。現環境 Node 22 / Unicode 16.0 冇問題。可選做法：lookbehind 明確加返 `‌‍`（對新 Node 冗餘無害，對舊 Node 穩定），或喺註解寫明需要 Unicode ≥ 15.1。
