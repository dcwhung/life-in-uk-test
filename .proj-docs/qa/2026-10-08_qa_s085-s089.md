| 類別 | Case | 結果 |

| Keyword 喺行首 / 檔首 / 縮排 / `}` 後 | `\nreturn /x/`、檔首 `return /x/`、`{\n  return /x/`、`}return /x/` | 4/4 ✅ |

| 理論 miss | `this.#of / 2`、`this.#in / 2`、`éin / 2` | 0/3 ❌（見下） |

  對照 S-088 之前（`ca7c52e`）：同一 probe 有 7 個 miss（`x$of`、`$return`、`o.\nof`、`o .  in` + 上面 3 個）→ S-088 修好 4 個，冇引入新 miss。
- **理論 miss（S 建議，唔開 CUI）**：
  - Private name `#in` / `#of` / `#return`：`#` 唔喺 `[\w$]`，所以 `this.#of / 2` 會被當 regex 開頭，可能吞走後面嘅 code（false negative）
  - Non-ASCII identifier（`éin`）：`\w` 唔包 non-ASCII letter
  - 實際影響：`grep` `js/` 冇任何 `class` / private field，亦冇 non-ASCII identifier → 現時 0 影響。如要收緊，可將 lookbehind 改為 `(?<![\w$#\p{L}]|\.\s*)` 加 `u` flag，再補 2 個 sample；建議登記為 S-090（低優先），由 reviewer / main agent 決定
- 註：`\s*` 冇 `m` flag，`$` = `out` 結尾，所以 `\.\s*` 可跨行 —— 啱 JS 語義（`o.\nof` 係 property）
